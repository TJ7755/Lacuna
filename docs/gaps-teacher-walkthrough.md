# Gaps teacher walkthrough

Status: prepared for a later session. **No teacher usability session has been run.**
Automated browser checks and an operator's rehearsal do not replace that evidence.
Use synthetic pupils and a disposable course, never a real class's records.

## Prepare before the session

Allow 15 minutes with a teacher who has not used Gaps. A facilitator observes;
they do not explain which control to choose unless the teacher is stuck.
Use the teacher's normal device and browser, or record why that is not possible.

The facilitator prepares a published synthetic course with a pinned class key and
one synthetic report for a completed UTC day. Create it with **Create class**, copy the generated recovery code and download
its class recovery file under **Keep this private to reopen the class** before continuing.
Use **Give this to pupils** on **Invite** for the pupil class code or join link.
Keep the recovery file and code separately
available through a private channel. Legacy classes still use separate connection
and teacher recovery files with their existing passphrases; rehearse that flow
separately when it is relevant to the participant. Verify the report through the live relay first. Do not put credentials
or files in this document, public issues, recordings or screenshots.

Use a fresh browser profile for the participant, so neither connection nor key is
already saved. Tell them the file and recovery code belong to the demonstration class and were
prepared on another device. This session exercises recovery; observe first-time
creation separately, including saving the one-time code and file before continuing.
If no prepared report exists, postpone the results task rather than inventing one
or changing a pupil's clock. Daily delivery is checked after a UTC boundary.

Keep the [school notice](gaps-school-notice.md) available. The facilitator retains
the synthetic share's owner credential privately for cleanup after the session.

## Tasks to read aloud

| Time | Prompt | Observe without prompting |
| --- | --- | --- |
| 0–2 min | “What do you think this site does? What would you do first?” | Whether the next action and pupil choice are understood. |
| 2–6 min | “Open this demonstration class on this device, using the material provided.” | How they find restore, enter the recovery code, use the remember checkbox and respond to wrong-file or wrong-code errors. |
| 6–9 min | “Show me what you would give pupils so they can join.” | Whether they choose the code/link and keep the recovery file and code private. Ask what happens before a pupil chooses to share. |
| 9–12 min | “Find the prepared report for this day. What would you revisit with this pupil? What can you conclude if there is no report?” | Date selection, reading activity/criterion detail, unknown or self-marked evidence, and whether missing data is mistaken for no study. |
| 12–15 min | “Finish safely, then tell me how you would open this class tomorrow or on another device.” | Close or Lock, forgetting remembered access, recovering access, and the distinction between local removal and deleting relay data. |

Ask the participant to explain their expectation before an uncertain click.
Record where the interface contradicted it. If stuck for a minute, offer the
smallest hint and record its exact wording. Stop a task that would expose a secret
or delete anything beyond the synthetic class.

## Record after the session

Record the date, browser/device and whether the participant had prior Lacuna
experience. Use a participant code, not a pupil or teacher name, in public evidence.

For each task record completion (unassisted, assisted or not completed), elapsed
time, wrong turns, hints and the participant's words. Record no recovery codes, passphrases,
connection contents, pupil records or owner credentials. Ask:

- Which step was least clear?
- What would you expect to happen tomorrow?
- What information would you need before using this with a class?

Treat sharing a credential file, misunderstanding consent, confusing missing
reports with no study, or being unable to regain access as a trial blocker to
investigate. File concrete reproductions; do not turn one participant's preference
into a new dashboard feature by default.

Afterwards, delete the synthetic share using its owner control and verify its
public payload is gone. This removes its relay reports too. Remove the disposable
browser profile and securely discard demonstration files, recovery codes and passphrases when no
longer needed. Record cleanup success or the exact outstanding limitation.
